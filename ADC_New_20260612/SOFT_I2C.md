# 软件 I2C 检查与修复

按产品固件检查 `SoftIIC.c`、`SoftIIC_PP.c` 及通用命令、产品采集和 MCP4725 的实际调用。保持新版引脚、8 位总线地址以及外部命令/结果布局。

## 已确认并修复的问题

- 推挽驱动收到 ACK 后立即拉低 SCL，无法保证第九个时钟的高电平脉宽；STOP 中 SCL 上升后立即释放 SDA，缺少建立时间。现保证 ACK 高电平至少 10 µs、STOP 建立时间至少 20 µs。旧驱动在新的时序回归中失败，修复后通过。
- 推挽 SDA 切回输出时总是先输出高电平，且主机 ACK 后主动输出高电平，可能与从机 ACK/下一字节的低电平竞争。现预装所需电平，发送末位及读取/ACK/NACK 阶段正确交接 SDA；ACK 后保持输入，末字节用释放 SDA 的 NACK 结束。
- 开漏驱动只把 SCL 输出置 1，没有读取实际电平。从机时钟拉伸时可能提前采样或丢失时钟。现所有时钟上升均等待引脚实际变高，默认最多轮询等待 `IIC_SCL_TIMEOUT_US=1000` 个 1 µs 延时；失败锁存到每条总线的 `I2CInfo.error`，退出并释放总线。实际等待还包含 GPIO/循环开销。
- NACK 等待函数和上层重复发 STOP；第二次 STOP 会在 SCL 高时先拉低 SDA，形成额外 START。现由事务拥有者统一 STOP，并先确保 SCL 低，再建立 SDA 低。反初始化直接断开 GPIO，不先拉低空闲总线。
- 总线异常没有恢复路径。现 START 前检查 SDA，最多发送九个恢复时钟并 STOP；恢复失败返回 1，下一次事务可重新尝试。读取中或 STOP 时的异常也返回失败，并清零本次读取缓冲。WF2200/WF3050 的开漏采集复用该读接口，不再把读超时当成功。
- 多字节 API 使用 8 位循环计数器处理 32 位长度，超过 255 字节会回绕。现计数器与长度一致。当前产品命令仍限制为 64 字节，未扩展外部协议。
- 公共 `delay_us()` 用计数器末尾的狭小窗口判定结束，中断跨过该窗口可能多等一轮约 65 ms，短延时的固定补偿也可能使延时不足。现累计 TIM1 的经过时间，不重置计数器；覆盖回绕和较长延时。TIM1 沿用新版 64 MHz / 64 分频，必须在调用前启动。

## 使用范围

| 总线 | 引脚 | 电气/协议要求 |
| --- | --- | --- |
| 产品开漏 I2C | PB4 SDA、PB5 SCL | 单主机；需要外部上拉；支持有界时钟拉伸及 SDA 卡住恢复 |
| DAC 开漏 I2C | PA12 SDA、PA11 SCL | 同一开漏驱动；MCP4725 地址字节为 0xC0；需要外部上拉 |
| 参考传感器推挽 I2C | PB7 SDA、PB6 SCL | 专用单主机参考总线；SCL 为推挽，从机必须不使用时钟拉伸；SDA 收数据/ACK 时转输入并开启内部上拉 |

`I2C_ReadNByte()` 接受 8 位地址并设置读位；`I2C_WriteNByte()` 的数组包含地址字节。保留 0=成功、1=通信失败，失败可能来自 NACK、超时或总线卡住。低层读取调用必须检查 `info->error`；现有业务已通过高层接口处理。硬件完全断开的输入通过上拉读高，返回 NACK。

WF100S 的模拟供电为 5 V，其他型号为 3.3 V；供电配置独立于 I2C GPIO 电气模式。通用命令继续采用 STOP 分隔的写后读，底层 START 接口仍可产生重复 START。

## 验证

在工程目录执行：

```sh
python3 tests/test_port.py
python3 tests/test_soft_i2c.py
```

测试直接编译真实驱动及产品适配器，用模拟 GPIO、线与从机解码校验地址、数据、时序和 SDA 驱动冲突，启用 AddressSanitizer/UndefinedBehaviorSanitizer。覆盖正常读写、逐字节 NACK、末字节 NACK、300 字节传输、短时钟拉伸、地址/ACK/数据/STOP 超时、永久 SCL/SDA 低、九时钟内恢复、失败后重试、重复 START、DAC 引脚，以及实际触发/选寄存器/读取流程。微秒延时测试使用 `main.c` 中的原函数体。

受影响编译单元通过 ARM GCC 编译检查；完整临时 GNU 固件链接通过。没有在 Keil 重新生成历史 HEX，也未连接实板。硬件验收还需确认两条开漏总线的外部上拉和上升时间，测量 START/STOP/ACK 波形，并连续读取产品和 DAC 确认实际响应；模拟测试无法代替这些电气测量。
